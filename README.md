# ベイズ診察エンジン — Bedside Bayes Engine

身体診察の価値を、尤度比・期待情報利得・到達可能域の3つで可視化する教育用ウェブアプリ。
事前確率に所見を積んで事後確率の軌跡を描き、**まだ取っていない所見を全部取ったときに到達しうる確率の分布**まで計算する。
「この診察は結論を変えるのか」に、その場で数量で答えるためのもの。

**公開URL: https://torukubota2023.github.io/bedside-bayes/**

- 依存ライブラリなし・ビルド不要・通信なし（`index.html` 単体でも動く）
- PWA 対応（ホーム画面に追加すればオフラインで起動）
- 設定と所見の状態が URL に入るので、**症例そのものをリンクで配れる**
- 対象：市中肺炎／胸水／急性心不全（救急外来の呼吸困難）／気流閉塞（COPD）
- [答え合わせノート](https://torukubota2023.github.io/kotaeawase-note/)の書き出し（**実測パネル**）を取り込み、自分の記録から出た感度・特異度・尤度比を文献値と並記できる（v2.9.0〜。端末内のみで扱い、URL には乗らない）

---

## このツールが答えようとしている3つの問い

1. **この所見は確率をどれだけ動かすか** — 事前確率に尤度比を積んだ軌跡
2. **次に何を診るべきか** — 未実施の所見を期待情報利得（bit）で順位づけ
3. **診察を続ける意味はあるか** — 残りの所見を全部取ったときに到達しうる確率の分布（到達可能域）

そして v2.0.0 では、4つ目の問いを加えた。

4. **その数字はどれくらい確かなのか** — 尤度比そのものの95%信頼区間を事後確率の幅として表示する

---

## 過大評価をどう防いでいるか

このアプリの最大の前提は**所見間の条件付き独立**である。しかし呼吸器・循環器の所見は同じ病態を別の窓から見ていることが多く、素朴に尤度比を掛け算すると確率を過大に見積もる。対策を2段構えで入れている。

### 1. 機序クラスタと相関補正 κ

各所見に「機序クラスタ」を持たせ、同一クラスタの n 番目の所見を `logLR × κⁿ` に減衰させる。強い所見から順に処理するので、最強の1つは満額、以降が割り引かれる。

| κ | 意味 |
|---|---|
| **1** | 素朴ベイズ（教科書どおりのLR掛け算） |
| 0.75 | 既定値 |
| **0** | 同一機序は最強の1つだけ採用する（と数学的に同値） |

肺炎パネルでヤギ音・気管支呼吸音・打診濁音（すべて肺実質化の所見）を陽性にすると、事前20%からの事後確率は **κ=1 で 93%、κ=0 で 61%** になる。この32ポイントの幅こそが、独立性の仮定が抱えているリスクの大きさである。

**κ を動かすと壊れる結論は、もともと脆い。**

### 2. 信頼区間

尤度比は点推定ではなく区間で報告される。たとえばヤギ音の LR+ 6.17 の95%信頼区間は 1.34–18.0 で、事前20%からの事後確率は **25%〜82%** の幅を持つ。点推定の 61% だけを見せるのは、決まっていないことを決まったように見せることになる。

軸に重ねた金色の帯がこの範囲である。区間が公表されていない所見は「区間不明」と明示し、その件数を判定欄に表示する。

## 尤度比の出典と信頼度

各所見には3種のバッジが付く。

| バッジ | 意味 |
|---|---|
| 出典 | 原著の報告値そのまま |
| 導出 | 報告された感度・特異度から計算 |
| 要確認 | 一次文献に到達できていない値。**教材としてそのまま使わない** |

**LR− が「―（報告なし）」となっている所見がある。** これは原著が陰性尤度比を報告していないか、有意でないとしたものである。仮の値を置くと「無いはずの情報」を作ってしまうため、あえて無情報（LR−=1）としてある。**陽性は強いが陰性は無意味**という所見は実在し、それ自体が教材になる。

## 計算の中身

| 項目 | 式 | 備考 |
|---|---|---|
| 事後オッズ | 事前オッズ × ΠLR | 相関補正 κ を適用 |
| 相関補正 | 同一クラスタの n 番目の所見を `logLR × κⁿ` に減衰 | κ=1 で素朴ベイズ、κ=0 で最強の1つだけ |
| 感度・特異度の復元 | `spec=(LR⁺−1)/(LR⁺−LR⁻)`, `sens=LR⁺(1−spec)` | 分岐確率の計算に使用 |
| 期待情報利得 | `H(p) − [P(+)H(p₊) + P(−)H(p₋)]` | 単位 bit。κ の減衰を反映 |
| 到達可能域 | 未実施 n 所見の 2ⁿ 分岐を全列挙 | 適用済み所見のクラスタ消費を引き継ぐ |
| 信頼区間 | 各所見の LR の95%CI を同じ経路で伝播 | 区間不明の所見は点推定で代用し件数を明示 |

## 所見パネルを自分のものにする

アプリ内の「＋ 所見を追加・LRを差し替える」から、所見名・LR+・LR−・機序クラスタを入力すれば即座に計算に入る。作ったパネルは JSON で書き出せる。
恒久的に組み込むなら `index.html` 内の `const DB = {...}` を直接編集する。疾患を1つ足すのは `DB` にキーを1つ増やすだけで済む。

```js
mydisease: {
  name:"表示名", short:"タブ名", pre:0.2, tTest:5, tTreat:70,
  ctx:"どんな患者集団を想定しているか",
  src:["出典1（PMID / DOI を必ず書く）"],
  f:[{ id:"a1", cat:"聴診", nm:"所見名", lp:6.2, ln:0.9,
       ci:[3.5,10.5],      // LR+ の95%信頼区間（不明なら省略）
       cin:[0.7,0.95],     // LR− の95%信頼区間（不明なら省略）
       cl:"機序クラスタ名", tag:"src", note:"補足" }],
  cases:[{ t:"症例名", d:"説明", pre:0.3, set:{a1:1} }]
}
```

`tag` は `src` / `der` / `chk`。`cl` が同じ所見どうしが相関補正の対象になる。
**LR− が報告されていない所見は `ln:1.0` にする**（仮の値を置かない）。

### 実測パネルの取り込み（答え合わせノート連携、v2.9.0〜）

[答え合わせノート](https://torukubota2023.github.io/kotaeawase-note/)は、画像を開く前の診察予測を記録して
POCUS で答え合わせするアプリで、(病態, 所見) ごとの実測 2×2 表から**あなた自身の**感度・特異度・尤度比
（95%信頼区間つき、最小 n = 病態あり・なし各10例）を書き出せる。その JSON を
「＋ 所見を追加・LRを差し替える」内の貼り付け欄から取り込むと、<b>実測</b> バッジつきで
文献値と**並記**される（置き換えない）。

取り込み時の契約（インターフェース）は次の形。ノート側と共通で、両実装がこのスキーマに固定されている。

```json
{"app":"kotaeawase-note","type":"personal-panel","version":1,"exportedAt":"<ISO8601>",
 "disease":{"noteId":"effusion","bedsideKey":"eff","label":"胸水"},
 "n":{"present":12,"absent":15},
 "findings":[{"id":"ef_fremitus_dec","nm":"触覚振盪の低下（実測）","cat":"触診",
   "lp":5.2,"ln":0.3,"ci":[1.8,15.1],"cin":[0.1,0.8],
   "counts":{"tp":9,"fp":2,"fn":3,"tn":13},"sens":0.75,"spec":0.87,"corrected":false}]}
```

`disease.bedsideKey` はこのアプリの疾患キー（`cap`=市中肺炎／`eff`=胸水／`hf`=急性心不全／`copd`=気流閉塞）。

取り込み時の検証と設計：

- **一組の規律を機械検証する。** `lp`/`ln` が `sens`/`spec` と ±1% で整合しない書き出しは、
  理由を示して拒否する。出所の混ざった組を通すと、表示頻度と期待情報利得の頻度が食い違い、
  確率が湧くからである（本体 DB と同じ規律）
- **検査として不成立の実測（LR+ ≤ 1）も拒否しない。**「実測では判別できず」と表示し、
  確率は動かさない（nsg と同じ扱い）。「あなたの実測ではこの所見は確率を動かさなかった」という
  記録自体が較正の教材である
- **プライバシー：実測パネルは端末のメモリ内でのみ扱う。** どこにも送信されず、
  共有リンク（URL ハッシュ）にも一切乗らない。保存もしないため、タブの切り替え・再読み込みで消える
  （使うたびに貼り直す）
- 実測所見は契約に機序クラスタ（`cl`）を持たないため、それぞれ独立のクラスタとして扱う。
  同じ手技の文献値と実測値を**両方**オンにすると κ 減衰で結ばれず二重計上になるので、
  比べるときは片方だけ押すこと

検証ロジックは `tests/personal_panel_import.test.mjs`（`node` で実行、41項目）でテストしている。

## 開発

ローカルで動かすだけなら `index.html` をブラウザで開けばよい。Service Worker と PWA は `http(s)` でのみ有効になる。

```bash
python3 -m http.server 8531
```

Service Worker はネットワーク優先・キャッシュ予備で動く。**`index.html` を更新したら `sw.js` の `VERSION` を必ず上げること。** 上げ忘れると、既に開いたことのある端末に古い版が配られ続ける。

## 更新履歴

### v2.12.0（2026-08-26）── 全パネルの重複計上を監査し、8件を修正

v2.11.0 で肺炎パネルを塞いだあと、**残る3パネルを独立監査役に監査させ、8件の要対処を検出**した。
監査は3つの型（内包／同一現象の別経路／集計結果型）で行い、**第4の型「診察者由来の相関」を新たに見つけた**。

#### 最優先：組み合わせの実測値を使う仕組み（`combos`）を新設

胸水の「胸郭拡張の左右差 × 打診濁音」は、**Kalantri 2007 がこの2つが揃ったときの尤度比を直接測っている**
（多変量2所見モデル AUC 0.88、両方陽性 LR+ 8.57 [5.4–13.4]・感度0.73/特異度0.91、両方陰性 LR− 0.29 [0.19–0.45]）。
ところが `exp` は `cl:"expand"`、`dull` は `cl:"fluid"` でクラスタが違い、κ が一切効かず 8.1×4.8＝38.9 の素通しだった。

| 事前20% | 修正前 | 修正後（＝原著の実測） |
|---|---|---|
| 両方陽性 | 90.7% | **68.2%**（区間 57–77%。原著CIと一致） |
| 両方陰性 | 0.74% | **6.8%** |

**どちらも原著の95%信頼区間の外に出ていた。** κ でも cl 統合でも届かない ── 同一クラスタにしても 86.8% で、
実測を再現するには κ=0.036（＝最強の1つだけ採る）が要る。**相関の源が生理ではなく診察者にある**ためで、
著者自身が「胸郭拡張を非対称と見た検者は、続く打診・呼吸音も異常に取りやすい」と限界に書いている。
そこで、原著が組み合わせで測った値をそのまま使う `combos` を新設した（掛け算より前に処理する。
向きが割れている組み合わせは原著が報告していないので、従来どおり個別に扱う）。

#### 内包排他（excl）の追加と、向きの修正

- **聴打診法 ⊂ 打診濁音**（胸水）── 同じ打診を耳で聴くか聴診器で聴くかの違い。同一コホートで聴打診法は
  全面的に劣り（LR+ 3.88／LR− 0.5 対 4.82／0.13）、**多変量で脱落**。76.9% → **54.5%**
- **肝頸静脈逆流 ⊂ 頸静脈怒張（陽性時のみ）**（心不全）── 腹部圧迫試験は「安静時の頸静脈が正常に見える
  患者で拾う」ための手技で、McGee Box 48.1 でも感度が JVD の倍以上（55–84% 対 10–58%）。
  **逆は成り立たない**ので非対称にした（JVD 陰性なら満額で効く）。93.5% → **77.3%**
- **ヤギ音 ⊃ 気管支呼吸音**（肺炎）── どちらも「実質化した肺が 300 Hz 超の高周波を胸壁まで通す」同じ物理を、
  同じ聴診器で、同じ部位で聴いている（McGee 第30章：正常肺はローパスフィルタ）。86.7% → **76.1%**
- **excl に向き `neg` を追加**（肺炎）── 内包は向きによって走る先が入れ替わる。「体温が高い」は
  「バイタルのどれかが異常」を含むが、「バイタルすべて正常」は「発熱なし」を含む。v2.11.0 は陽性側しか
  塞いでおらず、陰性側が漏れていた（4.6% → **5.9%**）

#### 値と分類の訂正

- **下腿浮腫・心雑音を `nsg`（確率を動かさない）へ**（心不全）── McGee 6th は下腿浮腫を Box 48.1・48.2 の
  両方で有意でないとし、Appendix Table 71.1 は LR+ 1.4 (0.6–3.2)／心雑音 2.2 (0.9–5.7) と区間つきで報告して、
  **このアプリの 2.30／2.60 との食い違いを名指ししていた**
- **クラックルの `cl` を impression → alveolar へ**（肺炎）── 発熱（全身性の炎症反応）と肺胞の液体貯留は
  別機序なのに同じクラスタで互いに減衰させていた。`cl` は「同じ生理学的機序のまとまり」と定義しているので、
  機序名と実態が食い違っていた（51.2% → **55.6%**、過小の解消）

#### 監査で「妥当」と確定し、変えなかったもの

- **声音共鳴と触覚振盪は内包ではない** ── McGee 第30章が周波数帯で分けている（触覚振盪 100–200 Hz、
  異常な声音共鳴は >300 Hz）。正常肺のローパスフィルタを挟んで反対側にあり、二度読みではない
- **聴診の喘鳴と自己申告の喘鳴も内包ではない** ── 一点観測と数週間の症状歴で、測っている対象が違う
- 心不全で検査（BNP・胸部X線）が診察所見と同じクラスタにあるのは**保守側**に働いている（別にすると 98.8%→99.5%）

#### 検証

- 8件すべてが監査の予測値どおりになったことを実測で確認（#1 は信頼区間 57–77% まで原著と一致）
- **予告と実挙動の一致を全パネル総当たり319件で照合し、食い違い0**（v2.11.0 で一度壊した箇所）
- コンソールエラー0。機序パネルに内部IDが漏れていないことを確認

#### 残件

- COPD「患者本人が申告する喘鳴」（LR 3.1）は出所未確認のまま保留 ── Straus 2000 全文の取り寄せ待ち。
  もし「自己申告の COPD 既往（LR 7.3）」の取り違えなら、**過去のスパイロメトリー＝参照基準を織り込んだ判断**
  なので集計結果型（excl 対象）に変わる
- 心不全の JVD・肝頸静脈逆流・浮腫は Wang 2005 Table 3 が未確認で、**信頼区間を持たない**（画面上で

### v2.2.0

「次の一手」の期待情報利得を、**bit という単位の意味から**説明する折りたたみ解説を追加した。数字の隣で読めないと単位の感覚は伝わらない。

- bit ＝「迷いの大きさ」。確率50%（＝最大限に迷っている）を 1 bit、0%/100% を 0 bit とする
- 確率と迷いの対応表（50%→1.00／70%→0.88／90%→0.47／95%→0.29／99%→0.08 bit）
- 「期待」が付く理由 ── やる前は陽性か陰性か分からないので、両方を起こりやすさで重みづけして平均している
- **なぜパーセントでなく bit なのか**：50%→60% は迷いが 0.03 bit しか減らないが、89%→99% は 0.42 bit 減る。同じ「10ポイント」でも減り方は14倍違う

あわせて「次の一手」の説明文を平易化し、**bit（確率がどれだけ動くか）と「判断が変わる確率」（閾値をまたぐか）の混同**を解いた。閾値のすぐ近くでは、bit が小さくても判断は変わる。この2つを併記している理由そのものである。

### v2.1.0

**相関補正が画面上ほとんど伝わっていなかった**ため、判定の直下に「⌁ 機序ごとの読み方」パネルを新設した。κ による減衰は v2.0.0 で実装済みだったが、表示は軌跡上の小さな灰色目盛りと減衰マークだけだった。

- 機序クラスタごとに、所属する所見・向き・オッズ寄与を一覧（クラスタの日本語表示名を新設）
- **「一致」と「食い違い」を判定**する
  - 同一機序で2件以上が同方向 → 「一致 n件 ── 確率はほぼ動かないが、取り違えの可能性は下がる」
  - 同一機序で向きが逆 → 「⚠ 食い違い ── どちらかが誤りの可能性。取り直しを」

**疾患のオッズと、所見そのものの確からしさは別の軸である。** 同じ機序を別経路で測り直しても疾患についての新しい証拠にはならないので確率は動かない。それでも一致した所見が増えれば「聞き間違い・触り間違いだった」可能性は下がる。ヤギ音の評価者間 κ が −0.10〜0.18 という世界では、この区別は実務的に重要になる。
