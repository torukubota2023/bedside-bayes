# ベイズ診察エンジン — Bedside Bayes Engine

身体診察の価値を、尤度比・期待情報利得・到達可能域の3つで可視化する教育用ウェブアプリ。
事前確率に所見を積んで事後確率の軌跡を描き、**まだ取っていない所見を全部取ったときに到達しうる確率の分布**まで計算する。
「この診察は結論を変えるのか」に、その場で数量で答えるためのもの。

**公開URL: https://torukubota2023.github.io/bedside-bayes/**

- 依存ライブラリなし・ビルド不要・通信なし（`index.html` 単体でも動く）
- PWA 対応（ホーム画面に追加すればオフラインで起動）
- 設定と所見の状態が URL に入るので、**症例そのものをリンクで配れる**
- 対象：市中肺炎／胸水／急性心不全（救急外来の呼吸困難）／気流閉塞（COPD）
- [答え合わせノート](https://torukubota2023.github.io/kotaeawase-note/)の書き出し（**実測パネル**）を取り込み、自分の記録から出た感度・特異度・尤度比を文献値と並記できる（v2.9.0〜。端末内のみで扱い、URL には乗らない）

---

## このツールが答えようとしている3つの問い

1. **この所見は確率をどれだけ動かすか** — 事前確率に尤度比を積んだ軌跡
2. **次に何を診るべきか** — 未実施の所見を期待情報利得（bit）で順位づけ
3. **診察を続ける意味はあるか** — 残りの所見を全部取ったときに到達しうる確率の分布（到達可能域）

そして v2.0.0 では、4つ目の問いを加えた。

4. **その数字はどれくらい確かなのか** — 尤度比そのものの95%信頼区間を事後確率の幅として表示する

---

## 過大評価をどう防いでいるか

このアプリの最大の前提は**所見間の条件付き独立**である。しかし呼吸器・循環器の所見は同じ病態を別の窓から見ていることが多く、素朴に尤度比を掛け算すると確率を過大に見積もる。対策を2段構えで入れている。

### 1. 機序クラスタと相関補正 κ ── ★既定は 1（＝減衰なし）。2026-08-27 に 0.75 から変更

各所見に「機序クラスタ」を持たせ、同一クラスタの n 番目の所見を `logLR × κⁿ` に減衰させる摘みがある。
強い所見から順に処理するので、最強の1つは満額、以降が割り引かれる。

| κ | 意味 |
|---|---|
| **1** | **既定。** 素朴ベイズ（教科書どおりのLR掛け算）＝減衰しない |
| **0** | 同一機序は最強の1つだけ採用する（と数学的に同値） |

#### なぜ既定を 1 にしたか ── κ に信頼区間を付けようとすると、κ のほうが壊れる

組み合わせの実測 LR に95%信頼区間が付いている文献は **Kalantri 2007 の1件だけ**。そこから κ を逆算する。

**陽性側**（単独 8.14 / 4.82、実測 LR+ 8.57、95%CI 5.4–13.4）

| 合わせる先 | 逆算される κ |
|---|--:|
| CI 上限 13.4 | 0.32 |
| 点推定 8.57 | **0.03** |
| CI 下限 5.4 | 解なし（κ=0 でも実測より大きい） |

→ κ ∈ [0, 0.32]。**旧既定の 0.75 は区間の外**（上限の2.4倍）。

**陰性側**（単独 0.29 / 0.13、実測 LR− 0.29、95%CI 0.19–0.45）

| κ | 到達する LR− |
|--:|--:|
| 1.00 | 0.038 |
| 0.75 | 0.051 |
| 0.00（最強の1つだけ） | 0.130 |
| **実測** | **0.29** |

→ **κ をどう動かしても実測に届かない。** κ=0 まで振り切っても行き過ぎている。

**κ は「重ねるほど弱まる」しか書けない。実測は「2つ揃ったときのほうが、いちばん強い1つだけより弱い」
と言っている。**単調減衰の関数形では、その形を表現できない。値の選び方の問題ではなく、式の形が
データに合っていない ── だから「それらしい割引率」を既定に置くのをやめた。

### ★ κ は1つの数字ではない ── 所見どうしの関係で決める（2026-08-27）

摘みを1つ置いて全部を同じ率で割り引くのをやめた。**関係が違えば、正しい κ も違う。**
上から順に見て、最初に当てはまった規則の κ を使い、**その規則名と理由を画面に出す。**

| # | 関係 | κ | 根拠 | 摘みで動くか |
|:-:|---|:-:|---|:-:|
| 1 | `excl` 内包（一方が他方を含む） | 採点外 | **論理** | — |
| 2 | `combos` 原著が「揃ったとき」を測っている | 実測値をそのまま | **実測** | — |
| 3 | **同じ現象（`phen`）を、もう一度測っている** | **0** | **原理**。2つ目は疾患の確率を動かさない | 動かない |
| 4 | 同じ現象を、別の窓から（検査 vs 身体所見） | 摘みの値 | 診察者由来の相関は掛からないが、生理は同じ | 動く |
| 5 | 同じ機序（`cl`）だが、見ている現象は違う | 摘みの値 | **仮置き**。実測が無い | 動く |
| 6 | 別の機序 | **1**（満額） | **原理**。重複計上は起きていない | 動かない |

**摘み（既定 0.25）が効くのは #4 と #5 だけ**── 実測も論理も無く、仮置きするしかない場所。
#3 と #6 は原理で決まるので摘みでは動かない。**作った数字が効く範囲を、1箇所に閉じ込めた。**

`phen`（物理現象）は bedside-layers で作った分類をそのまま持ち込んだ。`cl`（機序）より一段細かい ──
胸水の【胸腔内の液体】には5所見が入るが、打診濁音は「空気の層が消えた」、
声音共鳴・触覚振盪・呼吸音減弱は「伝わらない」で別の現象。前者と後者は #5（部分的に重なる）、
声音共鳴どうし・振盪どうしは #3（同じことを2回測った）。

| パネル | #3 が効く（同じ現象） | 備考 |
|---|---|---|
| 胸水 | 声音共鳴・触覚振盪・呼吸音減弱 | 打診濁音は別現象なので #5 |
| 肺炎 | ヤギ音・気管支呼吸音／バイタル・体温 | どちらも既に `excl` 済みで #3 まで来ない |
| 心不全 | JVD・肝頸静脈逆流・下腿浮腫／III音・起坐呼吸 | 胸部X線・BNP は検査なので #4 |
| COPD | 過共鳴・喉頭高 | ✅ **COPD既往×聴診の喘鳴×強制呼気時間>9秒 は combos（実測 LR 33）に入れた（v2.14.0）** |

**割り引きの根拠は、次の4種類しかない。作った数字は #4/#5 の摘み1つだけ。**

| 仕組み | 根拠の種類 |
|---|---|
| `excl`（内包排他） | **論理**。一方が他方を含む（体温 ⊂ バイタル）。推定値ではない |
| `combos`（組み合わせの実測値） | **実測**。原著が「揃ったとき」を直接数えている |
| `phen` が同じ | **原理**。同じ現象を2回測っても、疾患についての新しい証拠にならない |
| `cl` が同じ・`phen` が違う | **仮置き**（摘み。実測から逆算した上限 0.32 の内側） |

実測も論理も無い組み合わせには、**数字を作らず、画面にそう書く** ──
「この組み合わせを実際に測った研究はありません。個々の尤度比を掛けた値です。
実測がある組み合わせでは、掛け算は必ず大きく出ました（胸水の2所見: 掛け算 39.2 に対し実測 8.57）」。

摘みは残してある。肺炎パネルでヤギ音・気管支呼吸音・打診濁音を陽性にすると、事前20%からの事後確率は
**κ=1 で 93%、κ=0 で 61%** になる。この32ポイントの幅が、独立性の仮定が抱えているリスクの大きさである。

**κ を動かすと壊れる結論は、もともと脆い。**

### v2.15.0（2026-08-27）── 組み合わせの実測値を使ったあと、3つ目が満額で乗っていた

**① 不具合 ── combo が消費した現象・機序が、κ 規則エンジンに伝わっていなかった。**
`combos` で2〜3所見を1ステップにまとめたあと、その所見たちが属する現象（`phen`）と機序（`cl`）を
規則エンジンの計数器（`wp` / `wg`）へ記録していなかった。結果、同じ機序の次の所見が
**「別の機序」と判定されて満額で掛かっていた**。

| 局面 | v2.14.0 | v2.15.0 |
|---|---|---|
| 胸水：拡張差＋濁音＋振盪（すべて陽性） | 92.4% | **70.5%** |
| 胸水：同じ3所見がすべて陰性 | 1.4% | **6.2%** |
| COPD：組（LR 33）＋自己申告の喘鳴 | 97.8% | **93.4%** |

旧カウンタ `w[cl]` には記録していた（コメントにも意図が書いてある）が、規則エンジンへ
書き換えたとき、その手当てだけが古い変数に取り残されていた。
総当たりで測ると **胸水パネルの 2,187 状態のうち 468（21%）** が変わり、最大の差は
拡張差＋・呼吸音減弱−・濁音＋ の **17.6% → 54.6%**（治療閾値をまたぐ）。

⚠ **この不具合のいちばん質が悪いところ:** その局面では κ を動かしても事後が動かないため、
画面は「摘みに寄りかかっていない＝確か」と表示していた。**過大評価が確信の顔をして出ていた。**
修正後は κ=0 で 68.2%、κ=1 で 92.4% と幅が出る。

**② 胸郭拡張の左右差を、ほかの胸水所見と同じ機序クラスタへ移した（`cl: expand` → `fluid`）。**
`exp` だけ別クラスタだったため、原著が実測した組（拡張差＋濁音 = 68.2%）より、
**実測のない組（拡張差＋声音共鳴 = 92.9%）のほうが強く出ていた。**
Kalantri 自身が「拡張を非対称と見た検者は、続く打診や呼吸音も異常に取りやすい」と
書いており、この相関が打診に限る理由はない ── 相関の源は機序ではなく診察者なので、
機序で束ねる `cl` には原理的に届かない。現象（`phen: expand_lost`）は据え置いたので
κ=0 にはならず、部分的な重なり（`same-cl`）として扱われる。

拡張差＋声音共鳴は **92.9% → 76.4%**。

⚠ **この②により、㉑第11話の胸水デモ（呼吸音減弱＋ → 胸郭拡張差＋）が 91% → 75% に変わる。**
再撮と台詞2箇所（「事後確率91%」「83%から96%」）の差し替えが要る。
「1位に浮上したのは胸郭拡張の左右差」という順位の台詞は修正後も正しい（+35pt → +19pt、順位は不変）。
治療閾値は65%なので「確定域」の台詞もそのまま成立する。

### 2. 信頼区間

尤度比は点推定ではなく区間で報告される。たとえばヤギ音の LR+ 6.17 の95%信頼区間は 1.34–18.0 で、事前20%からの事後確率は **25%〜82%** の幅を持つ。点推定の 61% だけを見せるのは、決まっていないことを決まったように見せることになる。

軸に重ねた金色の帯がこの範囲である。区間が公表されていない所見は「区間不明」と明示し、その件数を判定欄に表示する。

## 尤度比の出典と信頼度

各所見には3種のバッジが付く。

| バッジ | 意味 |
|---|---|
| 出典 | 原著の報告値そのまま |
| 導出 | 報告された感度・特異度から計算 |
| 要確認 | 一次文献に到達できていない値。**教材としてそのまま使わない** |

**LR− が「―（報告なし）」となっている所見がある。** これは原著が陰性尤度比を報告していないか、有意でないとしたものである。仮の値を置くと「無いはずの情報」を作ってしまうため、あえて無情報（LR−=1）としてある。**陽性は強いが陰性は無意味**という所見は実在し、それ自体が教材になる。

## 計算の中身

| 項目 | 式 | 備考 |
|---|---|---|
| 事後オッズ | 事前オッズ × ΠLR | 相関補正 κ を適用 |
| 相関補正 | 同一クラスタの n 番目の所見を `logLR × κⁿ` に減衰 | κ=1 で素朴ベイズ、κ=0 で最強の1つだけ |
| 感度・特異度の復元 | `spec=(LR⁺−1)/(LR⁺−LR⁻)`, `sens=LR⁺(1−spec)` | 分岐確率の計算に使用 |
| 期待情報利得 | `H(p) − [P(+)H(p₊) + P(−)H(p₋)]` | 単位 bit。κ の減衰を反映 |
| 到達可能域 | 未実施 n 所見の 2ⁿ 分岐を全列挙 | 適用済み所見のクラスタ消費を引き継ぐ |
| 信頼区間 | 各所見の LR の95%CI を同じ経路で伝播 | 区間不明の所見は点推定で代用し件数を明示 |

## 所見パネルを自分のものにする

アプリ内の「＋ 所見を追加・LRを差し替える」から、所見名・LR+・LR−・機序クラスタを入力すれば即座に計算に入る。作ったパネルは JSON で書き出せる。
恒久的に組み込むなら `index.html` 内の `const DB = {...}` を直接編集する。疾患を1つ足すのは `DB` にキーを1つ増やすだけで済む。

```js
mydisease: {
  name:"表示名", short:"タブ名", pre:0.2, tTest:5, tTreat:70,
  ctx:"どんな患者集団を想定しているか",
  src:["出典1（PMID / DOI を必ず書く）"],
  f:[{ id:"a1", cat:"聴診", nm:"所見名", lp:6.2, ln:0.9,
       ci:[3.5,10.5],      // LR+ の95%信頼区間（不明なら省略）
       cin:[0.7,0.95],     // LR− の95%信頼区間（不明なら省略）
       cl:"機序クラスタ名", tag:"src", note:"補足" }],
  cases:[{ t:"症例名", d:"説明", pre:0.3, set:{a1:1} }]
}
```

`tag` は `src` / `der` / `chk`。`cl` が同じ所見どうしが相関補正の対象になる。
**LR− が報告されていない所見は `ln:1.0` にする**（仮の値を置かない）。

### 実測パネルの取り込み（答え合わせノート連携、v2.9.0〜）

[答え合わせノート](https://torukubota2023.github.io/kotaeawase-note/)は、画像を開く前の診察予測を記録して
POCUS で答え合わせするアプリで、(病態, 所見) ごとの実測 2×2 表から**あなた自身の**感度・特異度・尤度比
（95%信頼区間つき、最小 n = 病態あり・なし各10例）を書き出せる。その JSON を
「＋ 所見を追加・LRを差し替える」内の貼り付け欄から取り込むと、<b>実測</b> バッジつきで
文献値と**並記**される（置き換えない）。

取り込み時の契約（インターフェース）は次の形。ノート側と共通で、両実装がこのスキーマに固定されている。

```json
{"app":"kotaeawase-note","type":"personal-panel","version":1,"exportedAt":"<ISO8601>",
 "disease":{"noteId":"effusion","bedsideKey":"eff","label":"胸水"},
 "n":{"present":12,"absent":15},
 "findings":[{"id":"ef_fremitus_dec","nm":"触覚振盪の低下（実測）","cat":"触診",
   "lp":5.2,"ln":0.3,"ci":[1.8,15.1],"cin":[0.1,0.8],
   "counts":{"tp":9,"fp":2,"fn":3,"tn":13},"sens":0.75,"spec":0.87,"corrected":false}]}
```

`disease.bedsideKey` はこのアプリの疾患キー（`cap`=市中肺炎／`eff`=胸水／`hf`=急性心不全／`copd`=気流閉塞）。

取り込み時の検証と設計：

- **一組の規律を機械検証する。** `lp`/`ln` が `sens`/`spec` と ±1% で整合しない書き出しは、
  理由を示して拒否する。出所の混ざった組を通すと、表示頻度と期待情報利得の頻度が食い違い、
  確率が湧くからである（本体 DB と同じ規律）
- **検査として不成立の実測（LR+ ≤ 1）も拒否しない。**「実測では判別できず」と表示し、
  確率は動かさない（nsg と同じ扱い）。「あなたの実測ではこの所見は確率を動かさなかった」という
  記録自体が較正の教材である
- **プライバシー：実測パネルは端末のメモリ内でのみ扱う。** どこにも送信されず、
  共有リンク（URL ハッシュ）にも一切乗らない。保存もしないため、タブの切り替え・再読み込みで消える
  （使うたびに貼り直す）
- 実測所見は契約に機序クラスタ（`cl`）を持たないため、それぞれ独立のクラスタとして扱う。
  同じ手技の文献値と実測値を**両方**オンにすると κ 減衰で結ばれず二重計上になるので、
  比べるときは片方だけ押すこと

検証ロジックは `tests/personal_panel_import.test.mjs`（`node` で実行、41項目）でテストしている。

## 更新履歴

### v2.12.1（2026-08-26）── 「次の一手」の情報量を、着地点と整合させる

v2.12.0 で bit を実挙動基準に直した際、**頻度（陽性が出る見込み）を感度・特異度から、
着地点を実挙動から**取っていた。出所が割れたため、**平均した事後確率が事前に戻らなくなっていた**
（＝確率が湧く。全パネル42件で実測）。`eigInputs` の冒頭コメントが警告していたのと同じ型の誤りを、
そのコメントを読まずに踏んだ。

- **頻度を着地点から逆算する**形に統一した（`pp = (p−b)/(a−b)`）。画面に出る「出る見込み」も同じ値
- **p が a と b の間にない場合は算出不可の枠へ送る** ── 組み合わせの実測値があると実際に起きる。
  例: 胸水で打診濁音が陰性のとき、胸郭拡張も陰性にすると確率が**上がる**（2.4% → 6.8%）。
  原著の「両方陰性 LR− 0.29」は打診濁音単独の LR− 0.13 より弱い除外だからで、値の誤りではない
  （多変量2所見モデルと単変量で母数が違う）。この状態では「どれだけ迷いが減るか」を定義できない
- 検証: 全パネル293状態で**確率が湧く破れ0件・予告と実挙動の食い違い0件**

⚠ この修正により「次の一手」の順位が変わる。胸水で呼吸音減弱を陽性にしたとき、
1位は**打診濁音**（0.384 bit）で、胸郭拡張の左右差は2位（0.325 bit）。
組み合わせの実測値を持つ所見は、単独で押したときの価値が下がるため。
**㉑第11話の胸水デモのナレーション「1位に浮上したのは、胸郭拡張の左右差」は、この版と食い違う**
（確率の数値 57%・91%・83–96%・4.8% はすべて不変）。


### v2.12.0（2026-08-26）── 全パネルの重複計上を監査し、8件を修正

v2.11.0 で肺炎パネルを塞いだあと、**残る3パネルを独立監査役に監査させ、8件の要対処を検出**した。
監査は3つの型（内包／同一現象の別経路／集計結果型）で行い、**第4の型「診察者由来の相関」を新たに見つけた**。

#### 最優先：組み合わせの実測値を使う仕組み（`combos`）を新設

胸水の「胸郭拡張の左右差 × 打診濁音」は、**Kalantri 2007 がこの2つが揃ったときの尤度比を直接測っている**
（多変量2所見モデル AUC 0.88、両方陽性 LR+ 8.57 [5.4–13.4]・感度0.73/特異度0.91、両方陰性 LR− 0.29 [0.19–0.45]）。
ところが `exp` は `cl:"expand"`、`dull` は `cl:"fluid"` でクラスタが違い、κ が一切効かず 8.1×4.8＝38.9 の素通しだった。

| 事前20% | 修正前 | 修正後（＝原著の実測） |
|---|---|---|
| 両方陽性 | 90.7% | **68.2%**（区間 57–77%。原著CIと一致） |
| 両方陰性 | 0.74% | **6.8%** |

**どちらも原著の95%信頼区間の外に出ていた。** κ でも cl 統合でも届かない ── 同一クラスタにしても 86.8% で、
実測を再現するには κ=0.036（＝最強の1つだけ採る）が要る。**相関の源が生理ではなく診察者にある**ためで、
著者自身が「胸郭拡張を非対称と見た検者は、続く打診・呼吸音も異常に取りやすい」と限界に書いている。
そこで、原著が組み合わせで測った値をそのまま使う `combos` を新設した（掛け算より前に処理する。
向きが割れている組み合わせは原著が報告していないので、従来どおり個別に扱う）。

#### 内包排他（excl）の追加と、向きの修正

- **聴打診法 ⊂ 打診濁音**（胸水）── 同じ打診を耳で聴くか聴診器で聴くかの違い。同一コホートで聴打診法は
  全面的に劣り（LR+ 3.88／LR− 0.5 対 4.82／0.13）、**多変量で脱落**。76.9% → **54.5%**
- **肝頸静脈逆流 ⊂ 頸静脈怒張（陽性時のみ）**（心不全）── 腹部圧迫試験は「安静時の頸静脈が正常に見える
  患者で拾う」ための手技で、McGee Box 48.1 でも感度が JVD の倍以上（55–84% 対 10–58%）。
  **逆は成り立たない**ので非対称にした（JVD 陰性なら満額で効く）。93.5% → **77.3%**
- **ヤギ音 ⊃ 気管支呼吸音**（肺炎）── どちらも「実質化した肺が 300 Hz 超の高周波を胸壁まで通す」同じ物理を、
  同じ聴診器で、同じ部位で聴いている（McGee 第30章：正常肺はローパスフィルタ）。86.7% → **76.1%**
- **excl に向き `neg` を追加**（肺炎）── 内包は向きによって走る先が入れ替わる。「体温が高い」は
  「バイタルのどれかが異常」を含むが、「バイタルすべて正常」は「発熱なし」を含む。v2.11.0 は陽性側しか
  塞いでおらず、陰性側が漏れていた（4.6% → **5.9%**）

#### 値と分類の訂正

- **下腿浮腫・心雑音を `nsg`（確率を動かさない）へ**（心不全）── McGee 6th は下腿浮腫を Box 48.1・48.2 の
  両方で有意でないとし、Appendix Table 71.1 は LR+ 1.4 (0.6–3.2)／心雑音 2.2 (0.9–5.7) と区間つきで報告して、
  **このアプリの 2.30／2.60 との食い違いを名指ししていた**
- **クラックルの `cl` を impression → alveolar へ**（肺炎）── 発熱（全身性の炎症反応）と肺胞の液体貯留は
  別機序なのに同じクラスタで互いに減衰させていた。`cl` は「同じ生理学的機序のまとまり」と定義しているので、
  機序名と実態が食い違っていた（51.2% → **55.6%**、過小の解消）

#### 監査で「妥当」と確定し、変えなかったもの

- **声音共鳴と触覚振盪は内包ではない** ── McGee 第30章が周波数帯で分けている（触覚振盪 100–200 Hz、
  異常な声音共鳴は >300 Hz）。正常肺のローパスフィルタを挟んで反対側にあり、二度読みではない
- **聴診の喘鳴と自己申告の喘鳴も内包ではない** ── 一点観測と数週間の症状歴で、測っている対象が違う
- 心不全で検査（BNP・胸部X線）が診察所見と同じクラスタにあるのは**保守側**に働いている（別にすると 98.8%→99.5%）

#### 独立検証で見つかり、同日直したもの（新機構に付随する未処理）

主張した8件はすべて再現したが、`combos` と `excl` の**周辺**に未処理が残っていた。

- **ヤギ音の排他に向きが無かった** ── `excl:{ids:["bron"]}` に `pos` が無く、**陰性のヤギ音**
  （LR− 0.96＝ほぼ無情報）が陽性の気管支呼吸音を消していた（44.4% → 19.4%）。
  このコミット自身が書いた「内包は向きによって走る先が入れ替わる」に反していた。`pos:true` を付けた
- **「次の一手」の bit だけが実挙動を見ていなかった** ── 着地点は `postOf` を通るのに、順位を決める
  bit は素の尤度比から出ていた。胸水で打診濁音を陽性にすると、**値を下げたはずの胸郭拡張の左右差が
  0.329 bit で1位**に居座った（実挙動基準では 0.130 bit で最下位）。bit も `postOf` の着地点から出すようにした
- **相互排他のデッドロック** ── 「バイタルすべて正常（陰性）」と「体温37.8℃超（陽性）」を同時に押すと
  互いを採点外にし、**両方消えて事前確率に戻っていた**（38.5% → 20.0%）。矛盾入力を UI は止めないので、

- **combo がクラスタ消費を飲んでいた** ── 2所見を1ステップにまとめた結果、構成所見の `cl` が

### v2.11.0（2026-08-25）── 肺炎パネルの重複計上を構造で塞ぐ／軌跡を画面に固定

**軌跡パネルを画面上端に固定した（副院長要望）。** 所見を選んでいる間、検査閾値・治療閾値・
事後確率が見えていなければ「着地点がどちら側か」を見ながら押せない。所見一覧まで下りると
**軸の帯だけに縮む**（274px → 127px）。縮小は viewBox の切り出しで行い、描画は1系統のまま
── 2系統に分けると片方だけ古くなる。閾値ラベルは軸のすぐ上にも複製し、縮小時に消えないようにした。
横方向の中心追従（followTrack）は従来どおり効く。
⚠ 貼り付き検出に IntersectionObserver と requestAnimationFrame は**使っていない** ──
どちらもレンダリングが止まっている環境（隠れたタブ等）で発火せず、縮まないままになる（2026-08-25 実測）。
scroll を時間で間引く方式＋再描画時の再判定にした。


**なぜ変えたか。** 副院長の指摘（2026-08-25）──「総合的な臨床印象」は個々の所見を材料に
作られた判断なので、所見と掛け合わせると同じ情報を二度数える。従来は印象・バイタル・体温・
ラ音を同一クラスタに置いて κ で減衰させていたが、ヤギ音・気管支呼吸音・打診濁音（consol）と
胸郭拡張左右差（expand）は**素通しで掛け算されていた**（2タップで 20%→92% の作られた自信過剰。
第11話の「所見と掛け合わせてはいけません」は注意書きであって、構造では塞いでいなかった）。

- **内包排他 `excl` を新設**（κ とは別の仕組み。κ＝兄弟所見の部分相関の割引／excl＝親子関係の排他）
  - 臨床印象を適用中（陽性・陰性とも）→ 他の全所見が**採点外**（薄表示＋「織り込み済み」注記。
    トグル状態は消えず、印象を外せば復活）
  - 体温37.8℃超が陽性 → 「バイタル異常」が採点外（体温はバイタルの構成要素で、陽性が論理的に
    確定するため。バイタル異常の本体は陰性側＝すべて正常なら LR− 0.25 の除外）
- 採点外は事後確率・95%CI・機序パネル・**次の一手・到達可能域**のすべてから除外
  （順位に残すと「押せば動く」と予告しながら動かない ── v2.6.0 で踏んだ食い違いと同型になるため）
- 「次の一手」の下に採点外の専用枠を新設し、理由を明示
- **予告と実挙動を同じ式へ一本化**（独立検証で発覚・同日修正）。排他元の所見が「次の一手」に
  並ぶと、「いまの事後 × その所見のLR」で予告しながら、押した瞬間に既存の所見が採点外になって
  事前確率から計算し直されるため、**最大73.7ポイントずれていた**（例: 胸郭拡張+ 91.7% の状態で
  「印象を陰性なら86%」と予告 → 実際は11.9%）。着地点は `postOf()`＝押したときと同じ経路から出し、

### v2.2.0

「次の一手」の期待情報利得を、**bit という単位の意味から**説明する折りたたみ解説を追加した。数字の隣で読めないと単位の感覚は伝わらない。

- bit ＝「迷いの大きさ」。確率50%（＝最大限に迷っている）を 1 bit、0%/100% を 0 bit とする
